Nkuma 環境にメンバーを招待する

新しく nkuma を使い始める人を迎えます。管理者がやることは GitHub の招待だけで、あとは本人が利用者ガイドを見て進められます。

頻度: メンバーごとに 1 回 ・ 触るのは GitHub のみ (Azure には何も起きない)

手順

  1. GitHub アカウント名を聞く — 本人から受け取る (利用者ガイド「1.1 管理者に伝えるもの」で、本人側にもこの依頼が案内されています)
  2. GitHub organization nkuma-platform のチームへ招待する — これで次の 2 つが一度に付きます:
    • 配布リポジトリの読み取り (nkuma plugin とアプリテンプレの取得に必要)
    • エンジンイメージ (ghcr.io、private) の読み取り
  3. 「利用者ガイドを見てセットアップしてね」と URL を渡す — 前提ツール、権限づけ、plugin 導入は本人が進められます。詰まったら AI が案内する仕掛け (運転係) も入っています

クラウド版 Claude Code を使いたい人がいたら (任意)

クラウド版はセッションの GitHub アクセスが対象リポジトリ 1 つに絞られるため、private 配布物の取得に管理者側の追加設定が要ります:

  1. 配布リポジトリ限定・読み取り専用の fine-grained PAT を発行する
  2. クラウド環境 (environment) にセットアップスクリプトと合わせて配線する

手順の正本は開発リポジトリの cloud-environment.md (発行手順 / environment 設定 / 検証チェックリスト)。

迎えたあとの日常

  • 更新のアナウンス — nkuma の新版を配布したら (4 章)、メンバーに連絡します: plugin の新版なら「ターミナルで claude plugin update してね」、テンプレの新版なら「案件で /nkuma:nk-template-update してね」(手順の正本は更新ガイド)。更新は自動では届きません — 特にテンプレはこのアナウンスが既存案件へ届く唯一の発火条件です
  • 質問の受け口 — 利用者ガイドは「分からなければ管理者に聞く」設計です。よくある質問はガイドへ追記して育てます
