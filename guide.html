USER GUIDE

利用者ガイド — セットアップからサポートまで

nkuma は、Claude Code の上で動く南国ソフトの AI 開発基盤です。専門家 skill たちと対話しながら、顧客理解 → 設計 → 実装 → 公開まで一本の道で進めます。このページは「最初に何を揃えるか」から「困った時」までの正本です。

対象: nkuma を使い始める人 (エンジニアでなくても大丈夫)
1. 使う前の準備 2. nkuma の受け取り方 3. 最初の一歩 4. アプリを動かす 5. アプリを公開する 6. 困った時 7. 更新の受け取り方 8. 質問するには

1. 使う前の準備

1.1 GitHub アカウントを用意する (最初に 1 回)

nkuma の配布物はすべて GitHub 経由で届くので、最初に GitHub アカウントが必要です。まだ持っていない人は次の手順で作ります (無料プランで大丈夫です):

  1. github.com/signup を開く
  2. メールアドレス → パスワード → ユーザー名の順に入力する。ユーザー名は半角英数 (とハイフン) で、これがあなたの「GitHub アカウント名」になります (後で管理者に伝える名前です)
  3. 届いた確認メールのコード (またはリンク) で認証したら完了。プラン選択の画面が出たら Free のままで OK です

1.2 管理者に伝えるもの (最初に 1 回)

管理者 (taiga) に GitHub アカウント名 (1.1 で決めたユーザー名) を伝えて、以下を依頼してください:

  • GitHub organization nkuma-platform のチーム招待 (= 配布物の取得権限が付きます)
  • クラウド版 Claude Code を使いたい場合は、その旨もあわせて伝える (管理者側の設定が必要です)

1.3 コマンドの実行のしかた (ターミナルの開き方)

このページに出てくる「コマンド」は、すべてターミナル (黒い文字入力の画面) に貼り付けて Enter を押すだけです:

  1. ターミナルを開く — Windows はスタートメニューで「Git Bash」を検索して開く (git を入れると一緒に入ります。まだ git が無い段階では「PowerShell」でも OK)。Mac は Spotlight (⌘ + Space) で「ターミナル」を検索して開く
  2. コマンドを貼り付ける — このページのコマンド枠は右上の「コピー」ボタンでコピーできます。ターミナルに貼り付けて (Git Bash は右クリック → Paste、Mac は ⌘V) Enter
  3. 結果を読む — 例えば git --version と打って git version 2.45.0 のように版の数字が返れば「入っている」、command not found (コマンドが見つかりません) と返れば「まだ入っていない」です
ツールを入れた直後は、ターミナルを一度閉じて開き直してください。開きっぱなしのターミナルは新しく入れたツールを認識しないため、入れたのに command not found のままになります (Claude Code / git / gh / bun すべて共通)。

1.4 前提ツール (チェックリスト)

次の 6 つ (必須) を順に確認します。「確認方法」のコマンドをターミナルで実行して (1.3 のやり方)、版の数字が返れば OK。返らないものだけ「入れ方」で入れてください:

ツール確認方法入れ方
Claude Code (サブスクリプション + インストール)claude --versionclaude.com/claude-code の手順どおり (公式インストーラ)
gitgit --versiongit-scm.com (Windows はここで Git Bash も一緒に入ります)
gh CLI (GitHub 公式コマンド)gh --versioncli.github.com。入れたらログインへ → 1.5
Node.js (LTS 版)node --versionnodejs.org (LTS 推奨版のインストーラ)
bun (1.0 以上)bun --version下のコマンド 1 行 (この節のすぐ下)
Docker (Desktop)docker --versiondocker.com
Azure CLI (任意 — AI 機能 ($ai) をローカルで使う案件のみ)az --versionlearn.microsoft.com (Azure CLI)。入れたら az login で会社アカウントにログイン (API キーは使いません — §4)
Node.js と bun は両方必要です。アプリの実行環境は bun が担いますが、画面のブラウザ確認機能 (Playwright MCP) が Node.js 同梱の npx で起動するため、Node.js も入れてください (入れるだけで OK — 直接使う場面はありません)。
OS の前提: Windows は Git Bash 同梱の環境で使います (git のインストールで一緒に入ります)。Mac / Linux はそのままで OK。
ネットワークの前提: 初回のブラウザ確認機能が自動でブラウザ実体 (約 150MB) をダウンロードします。外部ダウンロードが制限されている環境では管理者へ相談してください。

bun の入れ方 (コマンド 1 行)

Mac / Linux はターミナルで:

curl -fsSL https://bun.sh/install | bash

Windows は PowerShell (または Git Bash) で:

powershell -c "irm bun.sh/install.ps1 | iex"

入れたらターミナルを閉じて開き直して bun --version — 版の数字が返れば完了です。

1.5 gh のログイン (最初に 1 回)

gh CLI を入れたら、GitHub アカウントと結びつけるログインを 1 回だけ行います:

  1. ターミナルで次を実行: 
    gh auth login --web
  2. いくつか質問が出ますが、すべてそのまま Enter (既定の選択) で大丈夫です (GitHub.com / HTTPS / Yes)
  3. ワンタイムコード (例: A1B2-C3D4) が表示されるので控えて、Enter を押すとブラウザが開きます
  4. ブラウザで GitHub にログイン → 控えたコードを入力 → Authorize github を押す
  5. ターミナルに戻って完了表示が出たら、確認: 
    gh auth status
    アカウント名と Logged in が表示されれば OK です

1.6 gh の権限づけ (最初に 1 回、チーム招待が済んでから)

gh の標準ログインでは足りない権限が 2 つあるので、まとめて 1 回で足しておきます:

  • workflow — 案件リポジトリには CI 設定 (ワークフローファイル) が含まれ、この権限がないと GitHub が push を拒否します
  • read:packages — アプリのデータ保存を担う共通基盤エンジンが private 置き場 (ghcr.io) の Docker イメージで届くため、その取得に必要です
gh auth refresh -h github.com -s repo,workflow,read:packages

ブラウザが開くので、表示されたコードを入力して承認します。承認画面に organization の一覧が出ますが、これは gh が既に持っているアクセス範囲の確認表示で、この操作で新たに加わるのは「ワークフローファイルの更新」と「パッケージの読み取り」だけです。

続けて、エンジンを取得できるように docker をログインさせておきます:

gh auth token | docker login ghcr.io -u $(gh api user -q .login) --password-stdin
この手順は期限切れがなく、マシンごとに 1 回だけです (同じ GitHub アカウントでも、PC が変われば再度必要です)。やり忘れても、必要になった場面で AI が同じ手順を案内してくれます (workflow は nk-init の環境チェック、read:packages はエンジン取得時の運転係)。

2. nkuma の受け取り方 (plugin の導入)

案件フォルダ (どこでも OK) でターミナルから claude と打って Claude Code を開き、次の 2 コマンドを1 つずつ実行します (gh 認証済みの資格で取得されます):

/plugin marketplace add nkuma-platform/nkuma-marketplace
/plugin install nkuma@nkuma-marketplace

導入できたかの確認: Claude Code を再起動して /nkuma:nk-master と打ち、skill が起動すれば OK です。

skill の呼び出しは常に /nkuma: 付き (例: /nkuma:nk-init)。名前空間なし (/nk-init) では起動しません。

3. 最初の一歩 (新しい案件の始め方)

  1. 案件用の空のフォルダを作り、そこで Claude Code を開く
  2. /nkuma:nk-init を実行 — キックオフの専門家が、環境チェック → 案件リポジトリの初期化 → 顧客理解のインタビューまで対話で導きます
  3. 以降は迷ったら /nkuma:nk-master — チームリーダー役が現在地を把握して、次に話すべき専門家 (設計対話 / 実装 / QA など) へ案内します

旅の全体像 (各 skill が案内するので暗記は不要です):

nk-init (キックオフ) → nk-domain-talk (顧客理解・設計) → nk-sprint-talk (何を作るか決める)
→ nk-poc-setup (動く土台を展開) → nk-dev-worker (実装) → nk-qa (テスト) → nk-ship (公開)

4. アプリを動かすとき (共通基盤エンジンの起動)

アプリの土台は、データ保存を担う共通基盤エンジン (Docker イメージ) と一緒に動きます。エンジンの起動は、案件で nkuma (AI) に頼めば運転係が行います — 起動前に最新エンジン版と照合し、差があれば「更新するか今のままか」を確認されるので、選ぶだけで大丈夫です。

手で起動する場合は、案件フォルダで bun run dataplane (テンプレに同梱のコマンド)。イメージ取得で 403 が出る場合は 1.6 の権限づけが未実施です。

AI 機能 ($ai) を使う案件のみ: 追加の準備

LLM (Azure OpenAI) はローカルに代替が無いため、開発中も開発用の実リソースを呼びます。準備は 2 つだけ — ① Azure CLI を入れて az login (いつもの会社アカウントでログイン。API キーは一切使いません — あなたのログインがそのまま通行証になります)、② 開発用 AI リソースへのロール付与を環境管理者に依頼 (初回のみ。付与後の反映に数分かかることがあります)。設定場所は案件の docker-compose.yml のコメント欄です。オフラインや CI では stub モード (決め打ち応答) に切り替えられます。

5. アプリを公開するとき (人に共有できるようにする)

できたアプリを Azure に公開してログイン付きで共有するには、nkuma に「公開したい」と言ってください (/nkuma:nk-ship)。手順の正本は案件リポジトリに同梱されている公開ガイド DEPLOY.md — nkuma が現在地を見て「いまどの段か・次に何をするか」を案内するので、ここでは全体像だけ掴めば十分です。

段やること誰のターン
① 依頼リポジトリ名・アプリ名・顧客名・初期 ADMIN (あなたのメールアドレス) の 4 点を環境管理者へ送る (雛形は nkuma が作ります)あなた
② 待ち管理者が受け入れ作業 (Azure 側の配線) を行う管理者
③ 配線管理者の返信にあるコマンド一式をそのまま実行する (すべて非秘密の識別子)あなた
④ リリースdeploy ブランチへマージする — これがリリースの引き金あなた
⑤ 配備GitHub Actions が構築 → 公開まで全自動で行う自動
⑥ 開通ログインを確認して URL を共有する。① で伝えたあなたのアカウントは初回の配備で自動的に管理者 (ADMIN) 登録済み — 誰かに登録をお願いする作業はありませんあなた
  • 公開の手順にあなたの Azure 権限や az コマンドは要りません — 使うのは gh だけで、Azure 側の操作はすべて管理者と CI が行います (AI 機能をローカル開発で使う場合の az login は§4 の話で、公開手順とは別)
  • 2 回目以降は「deploy へマージするだけ」で更新が公開されます
  • データが消えうる変更は自動で止まります (安全装置)。止まったら nkuma と一緒に内容を確認し、承認の操作は人が行います
  • 公開後、アプリの利用者管理 (メンバーの追加・権限変更) はアプリの管理画面 (/admin) で完結します — 利用したい人には URL を共有するだけ (ログインすると自動で登録されます)

6. 困った時の手引き

症状対処
/nkuma:nk-XXX が見つからない/plugin update → Claude Code 再起動。直らなければ /plugin uninstall nkuma@nkuma-marketplace → install し直し (何度やっても安全)
skill が古い挙動をする同上 (= 新しい版が配布されたのに update していない可能性)
ツールを入れたのに command not found のままターミナルを一度閉じて開き直す (開きっぱなしのターミナルは新しく入れたツールを認識しません)
gh 関連のエラーで止まるgh auth status を確認 → 未認証なら 1.5 のログイン (gh auth login --web)
nk-init が「スコープ不足」で止まる / push が拒否される1.6 の権限づけを実行 (= workflow が付いていない。標準ログイン直後や別 PC ではこの状態です)
エンジンイメージの取得で 4031.6 の 2 コマンドをやり直し (= read:packages が付いていない)
エンジンの版が合わないと言われるAI に起動を頼めば版の照合ごとやってくれます (手動なら案件の docker-compose.yml の版を案内された版に変更して起動し直し)
案件の CLAUDE.md の nkuma 欄が古い/nkuma:nk-init を再実行 — 初期化は何度実行しても安全 (既存の成果物は壊さず、設定・看板だけ最新化)
原則: nkuma の配布物 (skill / 設定 / エンジン) は「入れ直せば直る」ように作られています。手で直そうとする前に、update / 再実行を試してください。

7. 更新の受け取り方 (日々の運用)

  • 更新は自動では届きません。管理者が新しい版を配布した時だけ /plugin update で届きます (更新の案内は管理者から流れます)
  • エンジンの版更新は起動時に AI が自動で照合します (最新版があれば「更新するか今のままか」を確認されるので、選ぶだけで届きます)
  • 案件リポジトリに同梱されている仕組みの部品 (CI 設定・公開ガイドなど) の更新は、nkuma に「テンプレートの更新を適用して」 (/nkuma:nk-template-update) と頼むと、最新版との差分を見せてくれます — 適用するかはあなたが確認してから

8. 質問するには

分からないところは管理者 (taiga) に聞いてください — 全部を独力で突破する必要はありません。よくある質問はこのページに順次追記していきます。
