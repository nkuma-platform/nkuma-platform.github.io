USER GUIDE

nkuma のはじめかたと、
困った時の手引き。

nkuma は、Claude Code の上で動く南国ソフトの AI 業務アプリ基盤です。
専門家 skill たちと対話しながら、顧客理解 → 設計 → 実装 → 公開まで一本の道で進めます。
このページの手順どおりに進めば、はじめてでも迷いません。

対象: nkuma を使い始める人 — Claude Code がはじめてでも、エンジニアでなくても大丈夫
1. 全体像 2. 初回セットアップ 3. 案件フォルダと Claude アプリ 4. 最初の一歩 5. アプリを動かす 6. アプリを公開する 7. 困った時 8. 更新の受け取り方 9. 質問するには
OVERVIEW

1. 全体像 — 使う道具は 2 つだけ

nkuma の利用は、次の 2 つの道具の使い分けで成り立ちます:

⌨️ ターミナル 初回セットアップだけ 黒い文字入力の画面。§2 のコマンドを、コピーして貼り付けて Enter するだけです。
プログラミングの知識は要りません。
日常でここに戻るのは更新の時 (更新ガイド) くらい。
💬 Claude アプリ 毎日の利用はこちら デスクトップ版の Claude アプリ。
案件フォルダを開いて、nkuma の専門家たちと日本語で対話しながらアプリを作っていきます。

もう 1 つ、最初に知っておくと迷わない考え方があります:

「1 つの案件 (作りたいアプリ) = パソコンの中の 1 つのフォルダ」です。
nkuma との会話の記録も、できあがっていくアプリのコードも、ぜんぶその案件のフォルダの中に貯まっていきます。

新しい案件を始める = 空のフォルダを 1 つ作る。
続きをやる = 前と同じフォルダを開く。
それだけです (作り方・開き方は §3)。

このページの道のりは 4 歩です:

初回セットアップツールを入れて nkuma を受け取るターミナル・1 回だけ
案件フォルダを作る空のフォルダを 1 つ。
それが案件の器案件ごとに 1 回
nkuma と対話するClaude アプリでフォルダを開いて話す毎日ここ
動かして、公開するできたアプリを試し、チームへ届けるnkuma が案内
SETUP — STEP 1

2. 初回セットアップ (上から順に、1 回だけ)

この章は上から順に進めてください。
全部で 30〜60 分ほど、どの手順も 1 回きりです。

2.1 GitHub アカウントを用意する

nkuma の配布物はすべて GitHub 経由で届くので、最初に GitHub アカウントが必要です。
まだ持っていない人は次の手順で作ります (無料プランで大丈夫です):

  1. github.com/signup を開く
  2. メールアドレス → パスワード → ユーザー名の順に入力する。
    ユーザー名は半角英数 (とハイフン) で、これがあなたの「GitHub アカウント名」になります (後で管理者に伝える名前です)
  3. 届いた確認メールのコード (またはリンク) で認証したら完了。
    プラン選択の画面が出たら Free のままで OK です

2.2 管理者に依頼して、届いた招待に参加する

nkuma の配布物は GitHub organization「nkuma-platform」の中に置いてあります。
ここに参加していないと置き場そのものが見えないので、この節は 4 歩あります — 依頼して終わりではなく、届いた招待に参加するところまでです。

1
管理者に依頼する
管理者 (taiga) に GitHub アカウント名 (2.1 で決めたユーザー名) を伝えて、organization「nkuma-platform」のチーム招待を依頼してください。
これで配布物の取得権限が付きます。
2
招待メールが届くのを待つ
GitHub から「Invitation to join the nkuma-platform organization」のような件名のメールが届きます。
宛先は 2.1 で GitHub に登録したメールアドレスです。
見当たらない時は迷惑メールフォルダも確認してください。
3
メールの中の「Join」を押して参加する
メールのボタン (Join @nkuma-platform) を押すとブラウザが開くので、GitHub にログインした状態で参加を確定します。
ここまでやらないと参加は成立しません — メールが届いただけでは権限は付きません。
メールを消してしまった場合は github.com/nkuma-platform を開けば、未承諾の招待からその場で参加できます。
4
参加できたか確かめる
GitHub にログインした状態で github.com/nkuma-platform を開いてください。
組織のページ (リポジトリの一覧) が見えれば参加済みです。
「招待が届いています」の表示が残っていれば、まだ 3 が終わっていません。
ページが見つからない (404) 場合は、招待そのものがまだなので管理者に確認してください。
この 4 歩が済んでいないと、2.6 と 2.7 は必ず失敗します。
置き場が見えないためで、コマンドやパソコンの問題ではありません。
依頼と返事を待つ手順なので、初回セットアップの中でいちばん先に済ませておくのがおすすめです (他の手順は待っている間に進められます)。

2.3 ターミナルの開き方 (コマンドの実行のしかた)

このページに出てくる「コマンド」は、すべてターミナル (黒い文字入力の画面) に貼り付けて Enter を押すだけです:

1
ターミナルを開く
Windows はスタートメニューで「ターミナル」を検索して開く (見つからなければ「PowerShell」でも同じです)。
Mac は Spotlight (⌘ + Space) で「ターミナル」を検索して開く。
2
コマンドを貼り付けて Enter
このページのコマンド枠は右上の「コピー」ボタンでコピーできます。
ターミナルに貼り付けて (Windows は Ctrl+V または右クリック、Mac は ⌘V) Enter。
3
結果を読む
例えば git --version と打って git version 2.45.0 のように版の数字が返れば「入っている」、「認識されません」(Mac は command not found) と返れば「まだ入っていない」です。
ツールを入れた直後は、ターミナルを一度閉じて開き直してください。
開きっぱなしのターミナルは新しく入れたツールを認識しないため、入れたのに「認識されません」のままになります (Claude Code / git / gh / bun すべて共通)。

2.4 ツールを入れる (チェックリスト)

次の 7 つ (必須) を順に確認します。
「確認方法」のコマンドをターミナルで実行して (2.3 のやり方)、版の数字が返れば OK。
返らないものだけ「入れ方」で入れてください:

ツール確認方法入れ方
Claude アプリ (デスクトップ版 — 日常利用の主役)アプリを起動してログインできるclaude.ai/download からインストールして、会社で使っている Claude アカウントでログイン
Claude Code CLI (ターミナル用 — セットアップと plugin 管理で使う)claude --versionclaude.com/claude-code の手順どおり (公式インストーラ)
gitgit --versiongit-scm.com (Windows 用インストーラは設定を全部そのまま Next で OK)
gh CLI (GitHub 公式コマンド)gh --versioncli.github.com。
入れたらログインへ → 2.5
Node.js (LTS 版)node --versionnodejs.org (LTS 推奨版のインストーラ)
bun (1.0 以上)bun --version下のコマンド 1 行 (この節のすぐ下)
Docker (Desktop)docker --versiondocker.com。
入れたら起動もしておく → 2.6 (版の数字が返っても「起動している」とは限りません)
Azure CLI (任意 — AI 機能 ($ai) をローカルで使う案件のみ)az --versionlearn.microsoft.com (Azure CLI)。
入れたら az login で会社アカウントにログイン (API キーは使いません — §5)
  • Claude アプリと Claude Code CLI は別物で、両方必要です。
    アプリが日常利用の画面、CLI がターミナルからのセットアップ・plugin 管理の担当です (アプリを入れてもターミナルの claude コマンドは付いてきません)。
    アカウントは同じものでログインします。
  • Node.js と bun も両方必要です。
    アプリの実行環境は bun が担いますが、画面のブラウザ確認機能が Node.js 同梱の npx で起動するためです。
    Node.js は入れるだけで OK — 直接使う場面はありません。
  • OS の前提: Windows は標準の「ターミナル」で OK です (git のインストールだけは必須 — Claude Code が内部で使います)。
    Mac / Linux はそのままで OK。
  • ネットワークの前提: 初回のブラウザ確認機能が自動でブラウザ実体 (約 150MB) をダウンロードします。
    外部ダウンロードが制限されている環境では管理者へ相談してください。

bun の入れ方 (コマンド 1 行)

Mac / Linux はターミナルで:

curl -fsSL https://bun.sh/install | bash

Windows はターミナルで:

powershell -c "irm bun.sh/install.ps1 | iex"

入れたらターミナルを閉じて開き直して bun --version — 版の数字が返れば完了です。

Mac の人への補足 (2 つだけ)

Mac では次の 2 つでつまずくことがあります。
当てはまらなければ読み飛ばして構いません:

1
bun を入れたのに command not found のまま
bun のインストーラは、最後に設定ファイルへの追記コマンドを画面に表示します。
これを実行しないと、ターミナルは bun の置き場所を覚えません (開き直しても直りません)。
表示を見逃した場合は、次の 2 行を実行してからターミナルを開き直してください:
echo 'export BUN_INSTALL="$HOME/.bun"' >> ~/.zshrc
echo 'export PATH="$BUN_INSTALL/bin:$PATH"' >> ~/.zshrc
これは Mac 標準のターミナル (zsh) の場合です。
bun --version で版の数字が返れば完了です。
2
Azure CLI (az) を入れるなら Homebrew があると楽
Homebrew は Mac でソフトを入れるための道具です。
入っていれば Azure CLI は 1 行で入ります:
brew install azure-cli
Homebrew 自体が無ければ brew.sh のコマンドを実行してください。
インストールの最後に「次を実行してください」と 3 行ほど表示されます — その 3 行もコピーして実行しないと、brew コマンドが見つからないままになります (bun と同じ理由です)。
途中で分からなくなったら、画面つきで手順を追える記事があります → 【備忘録】Homebrew のインストール方法 (Zenn)

Azure CLI は「AI 機能 ($ai) をローカルで使う案件」だけ必要です (§5)。
使わない案件なら Homebrew ごと不要です。

2.5 gh のログイン

gh CLI を入れたら、GitHub アカウントと結びつけるログインを 1 回だけ行います:

1
ログインを開始する
ターミナルで次を実行:
gh auth login --web
いくつか質問が出ますが、すべてそのまま Enter (既定の選択) で大丈夫です (GitHub.com / HTTPS / Yes)。
2
ワンタイムコードで認証する
ワンタイムコード (例: A1B2-C3D4) が表示されるので控えて、Enter を押すとブラウザが開きます。
ブラウザで GitHub にログイン → 控えたコードを入力 → Authorize github を押す。
3
確認する
gh auth status
アカウント名と Logged in が表示されれば OK です。
4
git にもこのログインを使わせる
gh auth setup-git
画面には何も出ませんが、それで正常です (2.7 の受け取りと案件リポジトリの操作に必要です)。

2.6 gh の権限づけ (2.2 の参加が済んでから)

gh の標準ログインでは足りない権限が 2 つあるので、まとめて 1 回で足しておきます:

  • workflow — 案件リポジトリには CI 設定 (ワークフローファイル) が含まれ、この権限がないと GitHub が push を拒否します
  • read:packages — アプリのデータ保存を担う共通基盤エンジンが private 置き場 (ghcr.io) の Docker イメージで届くため、その取得に必要です
gh auth refresh -h github.com -s repo,workflow,read:packages

ブラウザが開くので、表示されたコードを入力して承認します。

承認画面に organization の一覧が出ますが、これは gh が既に持っているアクセス範囲の確認表示です。
この操作で新たに加わるのは「ワークフローファイルの更新」と「パッケージの読み取り」の 2 つだけです。

続けて、エンジンを取得できるように docker をログインさせておきます。
その前に Docker Desktop を起動してください — アプリを開いて、クジラのアイコンが動き出す (起動完了の表示になる) まで待ちます。
起動していないとこのコマンドは必ず失敗します。

gh auth token | docker login ghcr.io -u $(gh api user -q .login) --password-stdin
failed to get console mode for stdin: The handle is invalid. という行が出ますが、これは無視して構いません。
成功した時にも必ず出る行です。
最後の行が Login Succeeded になっていれば完了です。
Docker Desktop が起動していない時は、代わりに error during connect: ... the docker daemon is not running が出ます。
その場合は起動してからもう一度実行してください。
この手順は期限切れがなく、マシンごとに 1 回だけです (同じ GitHub アカウントでも、PC が変われば再度必要です)。
やり忘れても、必要になった場面で AI が同じ手順を案内してくれます (workflow は nk-init の環境チェック、read:packages はエンジン取得時の運転係)。

2.7 nkuma を受け取る (plugin の導入)

その前に 1 つだけ確認 — 2.2 の招待に参加しましたか?
依頼しただけ・メールが届いただけでは足りません。
参加が済んでいないと、下の 1 行目は必ず失敗します (受け取り先が見えないため)。
確かめ方は 2.2 の 4 — github.com/nkuma-platform を開いて組織のページが見えれば参加済みです。

承諾できていたら、nkuma 本体 (plugin) を受け取ります。ターミナルで次の 2 コマンドを1 つずつ実行してください (どのフォルダにいても OK。
Claude Code の画面を開く必要はありません):

claude plugin marketplace add https://github.com/nkuma-platform/nkuma-marketplace
claude plugin install nkuma@nkuma-marketplace

導入できたかの確認:

claude plugin list

nkuma@nkuma-marketplace が enabled と表示されれば完了です。

ターミナルで入れた plugin は、Claude アプリにもそのまま反映されます (設定が共有されています)。

1 行目の URL は必ず https:// 付きで貼ってください。
短縮形 (nkuma-platform/nkuma-marketplace) だと SSH という別方式の接続になり、SSH の鍵を設定していないパソコンでは失敗します。
plugin の操作はターミナル専用です。
Claude アプリの中で /plugin ... と打っても動きません (アプリの仕様)。
困った時 (§7) や更新 (更新ガイド) のコマンドも、すべてターミナルで実行します。
skill の呼び出しは常に /nkuma: 付き (例: /nkuma:nk-init)。
名前空間なし (/nk-init) では起動しません。
WORKSPACE — STEP 2 & 3

3. 案件フォルダを作って、Claude アプリで開く

初回セットアップが済んだら、ここからが日常の入口です。§1 のとおり「1 案件 = 1 フォルダ」— まず器になるフォルダを作り、それを Claude アプリで開きます。

3.1 案件フォルダを作る (新しい案件を始める時に 1 回)

1
置き場所を開く
Windows はエクスプローラー、Mac は Finder を開き、「ドキュメント」など自分の分かりやすい場所へ移動する。
2
空のフォルダを 1 つ作る
右クリック → 新規作成 → フォルダー (Mac は右クリック → 新規フォルダ)。
3
名前を付ける
フォルダ名は半角英数とハイフンで (例: kintai-app、uriage-kanri)。
日本語やスペース入りの名前は思わぬ不具合の元なので避けてください。
1 案件 1 フォルダを守ってください。
同じフォルダで別のアプリを作り始めると、nkuma が 2 つの案件を混ぜて理解してしまいます。
続きの作業はいつも同じフォルダ、新しい案件は新しいフォルダです。

3.2 Claude アプリでフォルダを開く (毎回の入口)

1
Claude アプリを起動する
Code の画面から新しいセッションを開始する。
2
実行環境は Local を選ぶ
自分のパソコンの上で動かす、という意味です。
3
案件フォルダを選ぶ
フォルダ選択 (Select folder) で、3.1 で作った案件フォルダを選ぶ。

これで nkuma と話す準備が整いました。
2 回目以降も同じ — アプリを開いて、同じ案件フォルダで新しいセッションを始めるだけです。

3.3 使うモデルを確認する (推奨: Claude Opus 5 以上)

Claude には性能の違う何種類かのモデル (AI の頭脳) があり、セッションごとに切り替えられます。
nkuma の専門家 skill たちは Claude Opus 5 以上のモデルで使う前提に調整されているため、それより軽いモデルや古いモデルで使うと、案内や生成物の質が下がることがあります。

1
いまのモデルを確認する
案件フォルダを開いたセッションのチャット欄に /model と入力して実行します。
いま使っているモデルと、選べるモデルの一覧が表示されます。
2
Opus 5 以上になっていれば OK
Opus 5 (またはそれより高性能なモデル) が選ばれていればそのままで大丈夫。
違うモデルになっていたら、一覧から選んで切り替えます。

新しい案件フォルダで最初のセッションを始めた時に、一度確認しておくのがおすすめです。
「専門家の案内がいつもより雑だな」と感じた時も、まずここを見直してください。

FIRST STEP

4. 最初の一歩 (新しい案件の始め方)

  1. 案件フォルダを Claude アプリで開いた状態で (§3)、チャット欄に /nkuma:nk-init と入力して実行 — キックオフの専門家が、環境チェック → 案件リポジトリの初期化 → 顧客理解のインタビューまで対話で導きます
  2. 以降は迷ったら /nkuma:nk-master — チームリーダー役が現在地を把握して、次に話すべき専門家 (設計対話 / 実装 / QA など) へ案内します

旅の全体像 (各 skill が案内するので暗記は不要です):

nk-init (キックオフ) → nk-domain-talk (顧客理解・設計) → nk-sprint-talk (何を作るか決める)
→ nk-poc-setup (動く土台を展開) → nk-dev-worker (実装) → nk-qa (テスト) → nk-ship (公開)
RUN

5. アプリを動かすとき (共通基盤エンジンの起動)

アプリの土台は、データ保存を担う共通基盤エンジン (Docker イメージ) と一緒に動きます。

エンジンの起動は、案件で nkuma (AI) に「動かして」と頼むだけです。
起動前に最新エンジン版との照合があり、差があれば「更新するか今のままか」を訊かれるので、選ぶだけで大丈夫です。

手で起動する場合は、案件フォルダで bun run dataplane (テンプレに同梱のコマンド)。
イメージ取得で 403 が出る場合は 2.6 の権限づけが未実施です。

AI 機能 ($ai) を使う案件のみ: 追加の準備

LLM (Azure OpenAI) はローカルに代替が無いため、開発中も開発用の実リソースを呼びます。
準備は 2 つだけです:

  1. Azure CLI を入れて az login — いつもの会社アカウントでログインします。API キーは一切使いません (あなたのログインがそのまま通行証になります)。
    ログイン後に「サブスクリプションを選んでください」と番号付きの一覧が出ることがありますが、そのまま Enter で大丈夫です (「既定のまま変更しない」という意味の選択肢です)
  2. 開発用 AI リソースへのロール付与を環境管理者に依頼 — 初回のみ。
    付与後の反映に数分かかることがあります

設定場所は案件の docker-compose.yml のコメント欄です。
オフラインや CI では stub モード (決め打ち応答) に切り替えられます。

SHIP

6. アプリを公開するとき (人に共有できるようにする)

できたアプリを Azure に公開してログイン付きで共有するには、nkuma に「公開したい」と言ってください (/nkuma:nk-ship)。

手順の正本は、案件リポジトリに同梱されている公開ガイド DEPLOY.md です。
nkuma が現在地を見て「いまどの段か・次に何をするか」を案内するので、ここでは全体像だけ掴めば十分です。

段やること誰のターン
① 依頼リポジトリの情報・アプリ名・顧客名・初期 ADMIN (あなたのメールアドレス) を環境管理者へ送る (雛形は nkuma が作ります — リポジトリの情報は自動で埋まるので、あなたが決めるのは残り 3 つです)あなた
② 待ち管理者が受け入れ作業 (Azure 側の配線) を行う管理者
③ 配線管理者の返信にあるコマンド一式をそのまま実行する (すべて非秘密の識別子)あなた
④ リリースdeploy ブランチへマージする — これがリリースの引き金あなた
⑤ 配備GitHub Actions が構築 → 公開まで全自動で行う自動
⑥ 開通ログインを確認して URL を共有する。① で伝えたあなたのアカウントは初回の配備で自動的に管理者 (ADMIN) 登録済み — 誰かに登録をお願いする作業はありませんあなた
  • 公開の手順にあなたの Azure 権限や az コマンドは要りません — 使うのは gh だけで、Azure 側の操作はすべて管理者と CI が行います (AI 機能をローカル開発で使う場合の az login は§5 の話で、公開手順とは別)
  • 2 回目以降は「deploy へマージするだけ」で更新が公開されます
  • データが消えうる変更は自動で止まります (安全装置)。
    止まったら nkuma と一緒に内容を確認し、承認の操作は人が行います
  • 公開後、アプリの利用者管理 (メンバーの追加・権限変更) はアプリの管理画面 (/admin) で完結します — 利用したい人には URL を共有するだけ (ログインすると自動で登録されます)
TROUBLESHOOTING

7. 困った時の手引き

症状対処
Claude アプリで /plugin ... が動かない・反応しないアプリの仕様です (故障ではありません)。
plugin の導入・更新・入れ直しは、すべてターミナルの claude plugin ... コマンドで行います (2.7 / 更新ガイド)
/nkuma:nk-XXX が見つからないターミナルで更新ガイドの 2 コマンド → Claude アプリのセッションを開き直す。
直らなければ claude plugin uninstall nkuma@nkuma-marketplace → 2.7 で入れ直し (何度やっても安全)
skill が古い挙動をする同上 (= 新しい版が配布されたのに更新していない可能性)
2.7 の marketplace add が失敗する順に確認: ① 2.2 の招待に参加済みか — いちばん多い原因です (github.com/nkuma-platform を開いて組織のページが見えれば参加済み。招待の表示が残っていれば、その場から参加できます) ② gh auth status でログイン済みか (2.5) ③ gh auth setup-git を実行したか (2.5 の最後) ④ URL を https:// 付きで貼ったか
2.6 の docker login が the docker daemon is not running で失敗するDocker Desktop が起動していません。
アプリを開いて起動しきってから、同じコマンドをもう一度実行してください (2.6)。
docker --version は起動していなくても版の数字を返すので、これだけでは判断できません
failed to get console mode for stdin と出る正常です (成功時にも必ず出る行)。
最後の行が Login Succeeded なら完了しています (2.6)
Mac で bun を入れたのに command not found のまま設定ファイルへの追記が済んでいません — Mac の人への補足の 2 行を実行してターミナルを開き直してください
ツールを入れたのに「認識されません」/ command not found のままターミナルを一度閉じて開き直す (開きっぱなしのターミナルは新しく入れたツールを認識しません)
gh 関連のエラーで止まるgh auth status を確認 → 未認証なら 2.5 のログイン (gh auth login --web)
nk-init が「スコープ不足」で止まる / push が拒否される2.6 の権限づけを実行 (= workflow が付いていない。
標準ログイン直後や別 PC ではこの状態です)
エンジンイメージの取得で 4032.6 の 2 コマンドをやり直し (= read:packages が付いていない)
エンジンの版が合わないと言われるAI に起動を頼めば版の照合ごとやってくれます (手動なら案件の docker-compose.yml の版を案内された版に変更して起動し直し)
案件の CLAUDE.md の nkuma 欄が古い/nkuma:nk-init を再実行 — 初期化は何度実行しても安全 (既存の成果物は壊さず、設定・看板だけ最新化)
原則: nkuma の配布物 (skill / 設定 / エンジン) は「入れ直せば直る」ように作られています。
手で直そうとする前に、更新 / 再実行を試してください。
UPDATE

8. 更新の受け取り方 (日々の運用)

nkuma の更新は自動では届きません。
管理者から「新しい版を配布しました」の案内が流れたら、更新の操作をします。

手順の正本は専用ページ「更新ガイド」です。
やることは 2 つ — plugin のアップデート (ターミナル、PC ごとに 1 回) と、テンプレートのアップデート (Claude アプリ、案件ごとに 1 回)。

エンジンの版更新はここに含まれません — 手元のエンジンは、アプリを動かす時に AI が最新版と照合して「更新するか今のままか」を訊いてくれます (§5)。
つながらない時は照合を飛ばして今の版のまま起動します — くわしくは更新ガイドへ。
