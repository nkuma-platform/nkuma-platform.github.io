第 2 章

DDD を決め切る

問い ①「何のために作ったのか、分からない」

答えドメインに即して作る — 作るものを明確にし、仕様にして作り上げる

  1. ① 何のために作ったのか、分からない
  2. ② 安全に動いているのか、分からない
  3. ③ 作った本人しか、使えない
DDD問い ①まとめる

「何のために作ったのか、分からない」— 問いは数え切れない。それを DDD の手法でまとめる。

業界は何か、どの業務が要か、何と何が関わるか、誰が使うか、言葉は何を指すか — 問いは尽きない。1 つずつ答えるのではなく、決まった型でまとめて答える — DDD (ドメイン駆動設計)。

DDD問い ①なぜ DDD か

設計の作法は、自作しない — Agent が学習済みの DDD なら、教え込まずに、作法どおりに動く。

DDD問い ①人の役目

人は自分の業務を話すだけ。Agent が DDD の専門家としてヒアリングし、文書にする。

DDD問い ①決め切る

ドメインだけではない — 決めておくべきことは多い。Nkuma はそれを 6 つの層に振り分ける。

中心は domain — 業務の語彙と構造。

第 3 章

安全

問い ②「安全に動いているのか、分からない」

答え構造で安全にする — 事故が「起こせない」構造

  1. ① 何のために作ったのか、分からない
  2. ② 安全に動いているのか、分からない
  3. ③ 作った本人しか、使えない
安全問い ②定義

安全とは — 事故が「起こせない」構造のこと。

注意深さに頼らないのは、AI が書いたコードの品質が揺れるから。

安全問い ②起きないこと

Nkuma で作ったアプリでは、こんな事故が起きない。

起こせない理由は 1 つ — 鍵・権限・記録・ファイルを持つのは共通基盤 (Nkuma が用意する全アプリ共通の土台) で、アプリは持たない。

7 つそれぞれの止まり方と、構造では守らないもの
  • 鍵の漏れ — アプリは鍵を持たない。接続の権限は、共通基盤だけが持つ
  • 他社・他アプリのデータ — 共通基盤が接続元を確かめ、宣言の外への到達を拒む
  • 全削除 — 危険な操作は共通基盤が止めるか、人の承認が要る
  • 戻せない — 自動バックアップから戻せる (標準構成で 7 日 — 復元の実演はこれから)
  • 記録なし — すべての書き込みを、共通基盤が記録する
  • ファイル流出 — ファイルは共通基盤を通してだけ読み書きする
  • ログインの穴 — ログインはいつもの ID を組み込むだけ、権限は共通基盤が強制する
  • 構造では守らないもの — 業務の計算の正しさ (それは品質の話。守るのは、情報と権限) / AI の出力の正しさ (構造が守るのは、秘密を持たせず、利用を記録するまで)
安全問い ②集約

アプリは、データに直接触れない — すべて共通基盤を通る。

安全問い ②強制

「共通基盤を使え」と指示するだけでは、すり抜けられる — だから SDK を作り、lint で強制する。

指示は忘れられるが、部品と検査は忘れない。

安全問い ②秘密のファイル

Agent の動きを監視し、秘密のファイルに触ろうとしたら、プログラムが強制キャンセルする。

外部サービスの鍵やパスワードは、コードの外のファイルに置かれる。下は、実際に止められた出力。

安全問い ②AI 自身

AI は、レビュー Agent の許可が無いと PR を作れない。

Nkuma は AI を使って開発していることを隠さない。下は、実際に止められた出力。

第 4 章

公開

問い ③「作った本人しか、使えない」

答え透明性のあるクオリティでリリースまで届ける — 合図ひとつで公開し、いつもの ID で使える

  1. ① 何のために作ったのか、分からない
  2. ② 安全に動いているのか、分からない
  3. ③ 作った本人しか、使えない
公開問い ③合図

作ったアプリは、合図ひとつで公開される。

作った本人以外が、いつもの ID でその日から使える。

公開問い ③ログイン

認証・認可は、アプリの外で済んでいる — アプリが考えるのは、ビジネスロジックだけ。

ログイン画面も認可のコードも書かない — ログインは会社の ID (Entra ID)、認可はロールの宣言 1 枚を置くだけで、強制するのは共通基盤。

公開問い ③検問

作ったアプリは、公開の前に 3 つの検問を通る。

公開問い ③版

公開のたびに、アプリの版が自動で刻まれる。

第 5 章

ドメインの上にアプリが展開されるメリット

3 つの答えが揃った場所には、ドメインの理解が残る。その上にアプリが展開されると、3 つのメリットが生まれる — いずれも実装はこれから。

  1. ① 作る Agent としてだけでなく、使う Agent としても働く

  3. ③ 作るだけで、AI から使われる口 (MCP) の形も自動で付く
展開のメリットメリット ①使う Agent

Nkuma は、作る Agent としてだけでなく、使う Agent としても働く。
