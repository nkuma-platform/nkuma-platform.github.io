NKUMA GUIDE

nkuma 使い方ガイド

nkuma は、Claude Code の上で動く南国ソフトの AI 開発基盤です。専門家 skill たちと対話しながら、顧客理解 → 設計 → 実装 → 公開まで一本の道で進めます。このページは「最初に何を揃えるか」から「困った時」までの正本です。

対象: 社内で nkuma を使い始める人 (エンジニアでなくても大丈夫)
1. 使う前の準備 2. nkuma の受け取り方 3. 最初の一歩 4. アプリを動かす 5. 困った時 6. 更新の受け取り方 7. 質問するには

1.使う前の準備

1.1 管理者に伝えるもの (最初に 1 回)

管理者 (taiga) に GitHub アカウント名を伝えて、以下を依頼してください:

  • GitHub organization nkuma-platform のチーム招待 (= 配布物の取得権限が付きます)
  • クラウド版 Claude Code を使いたい場合は、その旨もあわせて伝える (管理者側の設定が必要です)

1.2 前提ツール (チェックリスト)

ツール確認方法入れ方
Claude Code (サブスクリプション + インストール)claude --versionclaude.com/claude-code
gitgit --versiongit-scm.com
GitHub アカウント + gh CLI (認証済み)gh auth statuscli.github.com → gh auth login --web

Docker (Desktop)docker --versiondocker.com
OS の前提: Windows は Git Bash 同梱の環境で使います (git のインストールで一緒に入ります)。Mac / Linux はそのままで OK。
ネットワークの前提: 初回のブラウザ確認機能が自動でブラウザ実体 (約 150MB) をダウンロードします。外部ダウンロードが制限されている環境では管理者へ相談してください。

1.3 エンジン取得の権限づけ (最初に 1 回、チーム招待が済んでから)

アプリのデータ保存を担う共通基盤エンジンは、private 置き場 (ghcr.io) の Docker イメージで届きます。取得できるように、gh の認証に権限を 1 つ足して docker をログインさせておきます:

gh auth refresh -h github.com -s read:packages

ブラウザが開くので、表示されたコードを入力して承認します。承認画面に organization の一覧が出ますが、これは gh が既に持っているアクセス範囲の確認表示で、この操作で新たに加わるのは「パッケージの読み取り」だけです。

gh auth token | docker login ghcr.io -u $(gh api user -q .login) --password-stdin
この手順は期限切れがなく、マシンごとに 1 回だけです。やり忘れても、エンジンが必要になった場面で AI (運転係) が同じ手順を案内してくれます。

2.nkuma の受け取り方 (plugin の導入)

Claude Code を開いて、次の 2 コマンドを実行します (gh 認証済みの資格で取得されます):

/plugin marketplace add nkuma-platform/nkuma-marketplace
/plugin install nkuma@nkuma-marketplace

導入できたかの確認: Claude Code を再起動して /nkuma:nk-master と打ち、skill が起動すれば OK です。

skill の呼び出しは常に /nkuma: 付き (例: /nkuma:nk-init)。名前空間なし (/nk-init) では起動しません。

3.最初の一歩 (新しい案件の始め方)

  1. 案件用の空のフォルダを作り、そこで Claude Code を開く
  2. /nkuma:nk-init を実行 — キックオフの専門家が、環境チェック → 案件リポジトリの初期化 → 顧客理解のインタビューまで対話で導きます
  3. 以降は迷ったら /nkuma:nk-master — チームリーダー役が現在地を把握して、次に話すべき専門家 (設計対話 / 実装 / QA など) へ案内します

旅の全体像 (各 skill が案内するので暗記は不要です):

nk-init (キックオフ) → nk-domain-talk (顧客理解・設計) → nk-sprint-talk (何を作るか決める) → nk-poc-setup (動く土台を展開) → nk-dev-worker (実装) → nk-qa (テスト) → nk-ship (公開)

4.アプリを動かすとき (共通基盤エンジンの起動)

アプリの土台は、データ保存を担う共通基盤エンジン (Docker イメージ) と一緒に動きます。エンジンの起動は、案件で nkuma (AI) に頼めば運転係が行います — 起動前に最新エンジン版と照合し、差があれば「更新するか今のままか」を確認されるので、選ぶだけで大丈夫です。

手で起動する場合は、案件フォルダで bun run dataplane (テンプレに同梱のコマンド)。イメージ取得で 403 が出る場合は 1.3 の権限づけが未実施です。

5.困った時の手引き

症状対処
/nkuma:nk-XXX が見つからない/plugin update → Claude Code 再起動。直らなければ /plugin uninstall nkuma@nkuma-marketplace → install し直し (何度やっても安全)
skill が古い挙動をする同上 (= 新しい版が配布されたのに update していない可能性)
gh 関連のエラーで止まるgh auth status を確認 → 未認証なら gh auth login --web
エンジンイメージの取得で 4031.3 の 2 コマンドをやり直し (= read:packages が付いていない)
エンジンの版が合わないと言われるAI に起動を頼めば版の照合ごとやってくれます (手動なら案件の docker-compose.yml の版を案内された版に変更して起動し直し)
案件の CLAUDE.md の nkuma 欄が古い/nkuma:nk-init を再実行 — 初期化は何度実行しても安全 (既存の成果物は壊さず、設定・看板だけ最新化)
原則: nkuma の配布物 (skill / 設定 / エンジン) は「入れ直せば直る」ように作られています。手で直そうとする前に、update / 再実行を試してください。

6.更新の受け取り方 (日々の運用)

  • 更新は自動では届きません。管理者が新しい版を配布した時だけ /plugin update で届きます (更新の案内は管理者から流れます)
  • エンジンの版更新は起動時に AI が自動で照合します (最新版があれば「更新するか今のままか」を確認されるので、選ぶだけで届きます)

7.質問するには

分からないところは管理者 (taiga) に聞いてください — 全部を独力で突破する必要はありません。よくある質問はこのページに順次追記していきます。
