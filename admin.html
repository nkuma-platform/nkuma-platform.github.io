管理者ハンドブック

nkuma の環境管理者のためのハンドブックです。管理者の仕事を 1 つずつ、初めての人 (あるいは全部忘れた半年後の自分) が上から読んで実施できるように書いています。お客様側のインフラ担当の方が環境の中身を確認する用途にも使えます。

nkuma を「使う」側の話は利用者ガイドへ

章立て

1. Nkuma 環境を整備する

顧客 (または社内) の環境をゼロから開設する。全体像 → bicep で整備する (標準) → 手動で 1 つずつ建てる (理解と検証のための完全仕様)

 2. Nkuma 環境にメンバーを招待する

新しく使い始める人を迎える。GitHub org への招待と、その後に本人がやること

 3. Nkuma 環境にアプリを公開できるようにリポジトリを登録する

案件から「公開したい」と依頼が来たら。フェデレーション認証の登録から Variables の返信まで (受け入れ)

 4. Nkuma 環境を最新版にアップデートする

nkuma 本体 (plugin / テンプレ / エンジン / SDK / サポートページ) の配布と、顧客環境のエンジン更新

 5. 困ったとき・その他の作業

秘密 (API キー等) の投入、破壊的マイグレーションの承認、ロールバック、非常口、テスト面の建て壊し
道具の入手先: 環境整備・リポジトリ登録の道具一式 (foundation.bicep / 場面別 script + README / 記入用紙のサンプル) は公開リポジトリ nkuma-platform/nkuma-infra から git clone で入手し、以後 git pull で最新化します (配布物なので直接編集しない)。本ハンドブックは「何を・なぜ・どの順で」を掴むための正本で、実行時は道具側の README と並べて使ってください。
