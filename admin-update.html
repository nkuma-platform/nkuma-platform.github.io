ADMIN HANDBOOK — 4

Nkuma 環境を最新版にアップデートする

nkuma の配布はすべて pull 型です — 開発リポジトリにマージしただけでは誰にも届かず、管理者が版を刻んで publish した時だけ利用側が受け取れるようになります (マージ ≠ 配布)。この章は「何をどう publish し、それがどう届くか」の一覧です。

頻度: 更新のたび (版は人の意図で bump)
4.1 配布物を publish する 4.2 顧客環境のエンジンを新版にする

4.1 配布物を publish する (5 種)

配布物publish の仕方版の文法利用側への届き方
plugin (skill / subagent / hook)sync-marketplace.sh <版>vYYYYMMDD-連番各案件で /plugin update — メンバーへのアナウンスが必要 (自動では届かない)
アプリテンプレsync-template.sh <版>vYYYYMMDD-連番新規案件の展開 (nk-poc-setup) から。既存案件には反映されない (スナップショット)
エンジンイメージGitHub Actions release-dataplane-image を手動起動 (版名を入力)vYYYYMMDD-連番ローカル: 起動時に AI (運転係) が最新版と照合し、人が「更新するか」を選ぶ / 顧客環境: 4.2 の取り込み
SDK (nkuma-sdk)publish-sdk.sh <semver> (npm login 済みで)semver (例 0.1.0)公開 npm — 案件の bun update
サポートページ (このサイト)sync-support-site.sh (版なし)—即時 (push 後 1〜2 分で配信)
必要な持ち物: 配布リポジトリへの push 権 (org owner で充足) / エンジン publish 用の Actions secret NKUMA_GHCR_TOKEN (write:packages、設定済み) / npm の publish 権。
スクリプトの正本: 開発リポジトリの nkuma/scripts/ (各スクリプト冒頭に使い方コメントあり)。配布先リポジトリは毎回ゼロから再生成される sync の産物なので直接編集しない。

publish したら忘れずに: plugin の新版はメンバーに「/plugin update してね」のアナウンスを流す (2 章の連絡経路)。

4.2 顧客環境のエンジンを新版にする

エンジンの新版はデータのマイグレーションを含むことがあるため、顧客環境への適用は自動にせず、人の意図で行います。2 手です:

  1. 取り込み — 配布置き場 (ghcr.io) から顧客の Container Registry へ、版タグを指定して az acr import。取り込みに使う read:packages PAT は管理者の手元にだけ置き、顧客環境・リポジトリには残しません
  2. 差し替え — 記入用紙 (1.2) の dataplaneImage を新しい版タグへ変えて foundation を再実行
エンジンのシステムテーブル移行が絡む版は、エンジン側のリリースノートの手順に従ってください。コマンドの正本は開発リポジトリの infra/README「エンジンイメージの取り込み」。
