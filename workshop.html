WORKSHOP

nkuma ではじめての一本を作る。

勉強会で一緒に進む道のりのページです。
まず「何が作れるのか」を掴んで、自分の仕事から題材を 1 つ持ち込み、その日のうちに動くところまで作ります。
プログラミングの知識は要りません — 作るのは対話です。

対象: 勉強会に参加する人 — エンジニアでなくても大丈夫
1. 何が作れるのか 2. 当日までにできること 3. 何を作るか 4. 当日の道のり 5. お願い 6. 困った時
WHAT YOU CAN BUILD

1. nkuma で何が作れるのか

最初にここを掴んでください。
当日いちばん時間がかかるのは、作ることではなく「何を作るか」を思いつくところだからです。

nkuma で作れるものは、大きく次の 3 つの型でできています。
1 つだけでもアプリになりますし、組み合わせても構いません:

📋 貯める 入力したものがちゃんと残って、みんなが同じものを見られる。例: 備品の貸出台帳 / 設備の点検記録 / 案件の進捗表
🔑 人によって変わる ログインした人が誰かで、見えるもの・できることが変わる。例: 自分が出した申請だけ見える / 承認できるのは上長だけ
🤖 AI が読む・書く 写真や PDF を読み取って項目に起こす、文章を要約・分類する。例: 領収書を撮ると金額と日付が入る / 問い合わせ文を担当部署に仕分ける

自分で作らなくても、最初から付いてくるもの

次のものは、どのアプリにも共通で必要になるので nkuma 側が用意しています。
「これも作らなきゃ」と数えなくて大丈夫です:

ログイン 利用者の管理画面 権限の出し分け 誰がいつ何をしたかの記録 ファイルの添付 一覧表とグラフ 読み込み中の表示 バックアップ Azure への公開

今はまだできないこと

先に正直にお伝えしておきます。
次のものは、今の nkuma にはまだ届いていません:

  • リアルタイム通信 — 画面がひとりでに更新される仕組み。
    チャットの即時反映や、お知らせの通知
  • ログイン無しで誰でも見られる公開ページ — アプリは全体がログイン必須です
  • AI まわりの一部 — 応答が 1 文字ずつ流れる表示、社内文書を検索して答える仕組み、画像の生成
  • 基幹システムや SaaS との常時連携 — 別のシステムと自動でつながり続ける仕組み

これらは順に増えていきます。
当日「これをやりたい」が出たら、その場で教えてください — 次に何を足すかを決める材料になります。

BEFORE THE DAY

2. 当日までにできること (やってこなくても大丈夫)

セットアップは当日、会場で一緒にやります。
何も準備できていない状態で来てもらって構いません。
この章は「先にやっておくと当日が楽になること」の案内です。

先にやっておいてもらえると助かるのは、この 2 つだけです:

  • GitHub アカウントを作る (利用者ガイド 2.1) — 無料プランで大丈夫です
  • GitHub の道具を入れる (利用者ガイド 2.4 の git / gh CLI) — インストーラを実行するだけです

どちらも当日その場でできます。
できていなくても進行に支障はありません。

時間に余裕がある人は、利用者ガイドの初回セットアップを先に進めてもらっても構いません:

利用者ガイド 2. 初回セットアップ →

GitHub アカウントを作る → organization に参加する → ツールを入れる → gh にログインする → nkuma を受け取る。
この順で 1 本道です。

organization への参加 (利用者ガイド 2.2) は会場で行います。
招待を出すのも、参加を確認するのも、当日その場で一緒にやります。
事前に招待が届いていた人は、先に参加まで済ませておいてもらっても構いません。
途中で止まっても大丈夫です。
当日いちばんに解決しますので、どこで止まったかだけメモしておいてください。
「入れたのに認識されません」の多くは、ターミナルを一度閉じて開き直せば直ります。
YOUR IDEA

3. 何を作るか — 自分の仕事から 1 つ

当日作るものは、自分で持ち込んでください。
自分の仕事のものだから、できたときに嬉しいし、良し悪しの判断も自分でつきます。

探し方のコツは、次のどれかに当てはまる作業を思い出すことです:

  • 毎回 Excel で同じことをやっている
  • 紙とハンコで回している、あるいはメールで依頼が飛び交っている
  • 人に聞かないと分からない (どこにあるか、今どうなっているか)

思い浮かんだら、メモ 1 行で十分です。
細かいことは当日 nkuma と話しながら決めます。

思いつかない人向けのお題: SVG アイコンストア

業務で何度も使うアイコン (SVG) を 1 か所に集めて、探せるようにするアプリです。
「いつも誰かの PC の中にあって、探すのに時間がかかる」を解きます。

  • アイコンを名前とタグを付けて登録する
  • 一覧から探して、その場でダウンロードする
  • 名前の直しや削除など整理ができるのは管理者だけ
  • 誰がいつ何を足したかは自動で記録が残る

上の 3 つの型のうち「貯める」と「人によって変わる」を素直に通るお題です。
時間が余ったら「『会議で使うやつ』みたいな曖昧な言葉から、登録済みのタグの候補を AI に出してもらう」まで足せます。

THE DAY

4. 当日の道のり — 対話しながら進む

当日はまず、セットアップの仕上げを全員で一緒にやります (organization への参加 → 道具の確認 → nkuma の受け取り)。
ここは利用者ガイドの 2 をその場で一緒に進めるだけなので、事前に何もできていなくて大丈夫です。

その先が下の道のり — ここからは Claude アプリの中の話です。
コマンドを覚える必要はありません — 迷ったら /nkuma:nk-master が、いま何をすべきかを教えてくれます。

1
案件フォルダを作って、Claude アプリで開く
「1 つの案件 = パソコンの中の 1 つのフォルダ」です。
作り方と開き方は利用者ガイド 3 に画面つきで書いてあります。
2
/nkuma:nk-init — 何を作りたいのかを話す
キックオフ役が、環境を確認し、GitHub にあなたの案件リポジトリを作り、「誰の・どんな困りごとを・どう解くのか」を聞いていきます。
ここでたくさん話すほど、後の工程が楽になります。
3
リポジトリの名前を管理者に伝える 忘れずに
リポジトリができたら、その時点で管理者 (taiga) に伝えてください。
公開に必要な Azure 側の受け入れ作業を、あなたが作っている間に並行して進めてもらえます (ここを後回しにすると、公開のところで待ち時間になります)。
nkuma に「公開の依頼文を作って」と頼めば、必要な 4 点 — リポジトリ名 / アプリ名 / 顧客 (基盤) 名 / 初期管理者にする人のメールアドレス — を確認して文面を作ってくれます。
4
/nkuma:nk-master — いま何をすべきかを聞く
チームリーダー役です。
やることの一覧を見て、次に話す相手を教えてくれます。
道に迷ったら、いつでもここに戻ってきてください。
5
/nkuma:nk-sprint-talk — 今日どこまで作るかを決める
「今日ここまで動けば嬉しい」を一緒に決めて、作れる大きさに割ります。
欲張らず、1 つの画面が動くところを目標にするのがおすすめです。
6
動く土台を展開する
画面もログインもデータの置き場も入った土台が、/nkuma:nk-poc-setup で展開されます。
呼ぶ場所は nkuma が教えてくれるので、覚えなくて大丈夫です。
ここから先は「動くものを育てる」作業になります。
7
/nkuma:nk-dev-worker — 作って、動かして、見る
実装役です。
書いたら実際に画面を動かして自分の目で確認してから「できました」と言います。
出てきた画面を見て、違うと思ったらそのまま言葉で伝えてください — それが次の一手になります。
8
/nkuma:nk-ship — 公開する
形になったら Azure に公開して、ログイン付きの URL で人に共有できます。
手順 3 の受け入れが済んでいれば、あなたがやるのは案内どおりの数コマンドだけです。
Azure の権限も知識も要りません (くわしくは利用者ガイド 6)。
順番どおりに進まなくても大丈夫です。
行ったり来たりするのが普通ですし、話の流れで別の専門家に案内されることもあります。
迷子になったら /nkuma:nk-master に「いまどこ?」と聞けば、現在地から教えてくれます。
PLEASE

5. お願い — その日の会話を書き出す

差し支えなければ、当日の会話を書き出して管理者に渡してください。

nkuma は「人がどう話しかけたら、AI がどう動いたか」を見て良くしていきます。
うまくいった会話も、噛み合わなかった会話も、同じくらい役に立ちます — むしろ噛み合わなかった方が改善の材料になります。

1
セッションの終わりに、チャット欄で /export と打つ
ファイル名を決めたいときは /export 20260810-taro.txt のように続けて書きます。
2
保存先を選ぶ
ファイル名を付けずに実行すると、クリップボードにコピーするかファイルに保存するかを選ぶ画面が出ます。
どちらでも構いません。
3
できたものを管理者に渡す
中身はただの文章です。
その場で渡せなくても、後日で大丈夫です。
出せる分だけで十分助かります。
顧客の実名や社外に出せない情報が会話に含まれている場合は、その部分を消してから渡してください。
無理に出す必要はありません。
TROUBLESHOOTING

6. 困った時

当日は隣に管理者がいます。
詰まったらすぐ声をかけてください — 全部を独力で突破する必要はありません。

症状対処
/nkuma:nk-init と打っても反応しない先頭の /nkuma: が抜けていないか確認 (/nk-init では起動しません)。
それでも駄目なら更新ガイドの 2 コマンドを実行して、セッションを開き直す
会話が長くなって、話が噛み合わなくなってきた新しいセッションを同じ案件フォルダで始めて /nkuma:nk-master。
フォルダの中身とやることの一覧から現在地を読み直してくれます
作りたい機能が「できない」と言われた§1 の「今はまだできないこと」に当たっている可能性があります。
その場で教えてください — 別のやり方を一緒に探します
その他 (セットアップ・更新・エラー)利用者ガイドの「困った時の手引き」に一覧があります
